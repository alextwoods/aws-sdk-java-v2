# Schema serde porting deviations

This file records how SDK ports differ from their sources beyond the package rename (Requirement 1.2). Each section covers one ported module. Add a section per module as types are ported.

## `codegen-c2j-to-smithy` (C2J_Converter, tasks 1.20 and 1.21)

**Source.** `codegen-c2j-to-smithy/src/main/java/software/amazon/awssdk/c2j/smithy/C2jToSmithyConverter.java` (946 lines) on the `smithy-java-bridge` branch, taken from the local copy at `fork/smithy-java-bridge-alexwoo` (commit `ee9a74f69db`). That branch's only test, `ConvertAndAssembleTest`, is a `main` method.

**Target.** Package `software.amazon.awssdk.codegen.c2j2smithy`, module `codegen-c2j-to-smithy`. Compile-scope dependencies: `smithy-model`, `smithy-aws-traits`, `smithy-protocol-traits` (for `smithy.protocols#rpcv2Cbor`; already transitive through `smithy-aws-traits`), `smithy-rules-engine`, `smithy-waiters`, `jackson-core`, `jackson-databind`. Test scope adds `smithy-aws-endpoints`: validating a converted model needs the AWS rule-set built-ins (`AWS::Region`, ...) and functions (`aws.partition`, ...). The converter only copies the rule set, so it does not need that module, but the codegen pipeline's assembly stage (task 1.22) does.

### Input type: `C2jInput` instead of codegen's `C2jModels`

The source converter took a Jackson `JsonNode` for `service-2.json`. Its module depended on `codegen` only for `SmithyToServiceModel`, the inverse converter, which is not ported.

Task 1.20 asks the converter to take `C2jModels`. That type lives in `codegen` (`software.amazon.awssdk.codegen.C2jModels`) and holds codegen POJOs (`ServiceModel`, `Paginators`, `Waiters`, `EndpointRuleSetModel`, ...). `codegen` will depend on this module (task 1.22), so this module cannot depend on `codegen` without a cycle.

Decision: a converter-local input type, `C2jInput`, with the same contents as `C2jModels` but as Jackson trees: the service name, `service-2.json` (required), and optional `paginators-1.json`, `waiters-2.json`, `endpoint-rule-set.json` and `endpoint-tests.json`. `C2jInput.fromDirectory(serviceName, dir)` loads them from a `codegen-resources` directory.

- Why not an interface implemented in `codegen`: it would need one method per file returning a format-neutral value, which is a JSON tree anyway, and it would tie the converter's API to codegen's POJO shapes.
- Why not move the C2J POJOs out of `codegen`: they carry codegen-specific Jackson mappings and customization hooks, and the move would touch every C2J consumer in `codegen`.
- The name differs from `C2jModels` so that `CodegenPipeline` (task 1.22) can import both without a fully qualified name.
- Not a 1:1 file read: stage 2 of the Codegen_Pipeline applies C2J customizations to codegen's `ServiceModel` POJO. Task 1.22 must hand the customized model to the converter, for example as `ObjectMapper.valueToTree(serviceModel)`. Whether that tree keeps every C2J field that the converter reads (`jsonvalue`, `eventstream`, `wrapper`, `document`, `union`, `contextParam`, ...) is not verified here; task 1.22 needs a test that converts the raw file and the round-tripped POJO and compares the results. Done in task 1.22: `C2jServiceModelRoundTripTest` (see the `codegen` section).

### Standard traits (task 1.21)

The converter now reads all five C2J files and emits a standard trait for every row of design A.14's "Ported converter adds" table. The rule for markers: a marker carries only C2J information that no standard trait carries, and it is not emitted when that information is empty.

| C2J source | Emitted | Notes and deviations from the A.14 table |
|---|---|---|
| `metadata.protocols` (else `protocol`), `jsonVersion`, `protocolSettings.h2` | One trait per entry, in C2J order: `restJson1`, `awsJson1_0`/`awsJson1_1`, `restXml`, `awsQuery`, `ec2Query`, `smithy.protocols#rpcv2Cbor`. `h2: eventstream` → `http: [http/1.1, h2], eventStreamHttp: [h2]`; `optional` and `required` map similarly | Unknown protocol names get no trait and a `metadata.protocols=<name>` gap. CloudWatch gets `rpcv2Cbor`, `awsJson1_0` and `awsQuery` (Requirement 12.6) |
| `metadata.targetPrefix` | The service shape name | Not in the table. awsJson's `X-Amz-Target` and rpcv2Cbor's request path use the service shape name, so it must be the target prefix (`AmazonSQS`, `GraniteServiceVersion20100801`, `DynamoDB_20120810`), as in the published AWS Smithy models. When the prefix is absent, not a valid identifier, or collides with a shape or operation name ignoring case, the sanitized serviceId is used and `targetPrefix` stays on the metadata marker |
| `metadata.serviceId`, `endpointPrefix`, `signingName`, `uid`, `serviceFullName` | `aws.api#service(sdkId, endpointPrefix, arnNamespace, cloudFormationName, cloudTrailEventSource, docId)` and `@title` | `arnNamespace` = signingName, else endpointPrefix; `cloudFormationName` = sdkId without non-alphanumerics, capitalized; `cloudTrailEventSource` = `<arnNamespace>.amazonaws.com`; `docId` = uid. `serviceAbbreviation` stays on the metadata marker: smithy 1.71's `aws.api#service` has no `abbreviation` member |
| `metadata.auth`, else `signatureVersion`; operation `auth`, else `authtype`; `unsignedPayload` | `aws.auth#sigv4(name)`, `aws.auth#sigv4a(name)` (which also applies `sigv4`, as its selector requires), `smithy.api#httpBearerAuth`; `@auth` on the service only when its C2J default order differs from what Smithy derives from the applied auth traits; `@auth` on an operation only when it differs from the service default; `aws.auth#unsignedPayload` | `sigv4` name = signingName, else endpointPrefix. `none` → `@auth([])`; `smithy.api#noAuth` together with other schemes → `@optionalAuth` plus `@auth(others)`; `v4`, `s3`, `s3v4`, `iam` → sigv4; `v4a` → sigv4a; `v4-unsigned-body` → sigv4 plus `unsignedPayload`; `bearer` → httpBearerAuth. | `metadata.awsQueryCompatible` | `aws.protocols#awsQueryCompatible` | Only when the service has `awsJson1_0` or `rpcv2Cbor` (the trait's selector); otherwise dropped with a gap |
| `metadata.xmlNamespace` | Service `@xmlNamespace` | Now for every service that has it, not only `query`; derived as before when an awsQuery or ec2Query service lacks it |
| Exception `error.httpStatusCode`, `error.code`, `senderFault`, `fault` | `@error`, `@httpError(code)`, `aws.protocols#awsQueryError(code, httpResponseCode)` | `awsQueryError` is emitted whenever the wire code (C2J code, else the C2J shape name) differs from the Smithy shape name, for every protocol; `httpResponseCode` defaults to 400 or 500 by fault. Fault rule changed from the source: `fault: true` → server; else `senderFault` decides; else a status of 500 or more is server (CloudWatch `InternalServiceFault` has a 500 and no `senderFault`). The `error` marker is removed |
| `http.requestUri` labels | `@http` with each label renamed to the input member bound to it (`{Id}` → `{HostedZoneId}`, `{resource-arn}` → `{ResourceArn}`), greedy `+` and query literals kept (`UriLabels`) | The `locationName` marker stays on the member (design: "`#locationName` kept"). A label bound to no `location: uri` input member, or a URI Smithy cannot parse, fails the conversion with `C2jConversionException` naming the operation (Requirement 17.14); the source's `operation.http.requestUri` gap is gone. The `http` marker is now emitted only for operations with no `@http` (RPC protocols), per the table |
| `httpChecksum` | `aws.protocols#httpChecksum` | Unknown properties of the block are recorded as `operation.httpChecksum.<property>` gaps |
| `requestcompression.encodings` | `@requestCompression(encodings)` | Same unknown-property rule |
| `endpoint.hostPrefix` | `@endpoint(hostPrefix)`, and `@hostLabel` on each input member a label names | Smithy only allows `@hostLabel` on a required member targeting a string. If any label of a prefix does not qualify, the operation keeps the `hostPrefix` marker and gets no `@endpoint` |
| `staticContextParams`, `operationContextParams`, member `contextParam`, `clientContextParams` | `smithy.rules#staticContextParams`, `operationContextParams`, `contextParam`, `clientContextParams` | Values copied unchanged (the C2J and Smithy shapes match) |
| `endpointoperation`, `endpointdiscovery`, member `endpointdiscoveryid` | Service `aws.api#clientEndpointDiscovery(operation, error)`, `aws.api#clientDiscoveredEndpoint(required)`, `aws.api#clientEndpointDiscoveryId` | C2J does not name the invalid-endpoint error. The converter uses an `InvalidEndpoint*` error that every discovered operation declares; when there is none (DynamoDB), the trait has no error, the service gets `@suppress(["ClientEndpointDiscovery.MissingErrorDefinition"])`, and an `endpointdiscovery.error` gap is recorded. `endpointdiscovery` without an `endpointoperation` in the service gets no trait and a gap |
| `eventstream: true` structure, `event: true` | `@streaming` union; event structures get no trait | Event membership is implied by the union. `eventstream` and `event` markers removed. Union members never get `@required` |
| member `queryName` | `aws.protocols#ec2QueryName` | — |
| string `enum` | IDL 2 `enum` shape with `@enumValue` members | Member names are synthesized from values: characters outside `[A-Za-z0-9_]` become `_`, a leading digit gets a `_` prefix, a value with no letters or digits becomes `VALUE_<index>`, and names unique ignoring case get `_2`, `_3`, ... The SDK names constants from values, so only validity matters. Duplicate values are dropped. An enum with an empty value stays a string with the legacy `@enum` trait and a `shape.enum(empty value)` gap |
| `box` | Dropped | IDL 2 members are optional unless `@required` or `@default`, and the converter emits no `@default` |
| `required` | `@required` plus `@clientOptional` on every required structure member | C2J `required` is not a client-side guarantee: the SDK keeps required members nullable. `@clientOptional` says exactly that |
| `pattern` | `@pattern` | An invalid regular expression is dropped with a `shape.pattern(invalid)` gap instead of failing the conversion |
| `jsonvalue` | `@mediaType("application/json")` on the target | `@mediaType` is only valid on string and blob shapes, not members. A target used only by `jsonvalue` references gets the trait; a target also used elsewhere is copied as `<Name>JsonValue` (unique ignoring case), the copy gets the trait and a `shapeName` marker, and only the `jsonvalue` references target it. `jsonvalue` marker removed |
| `location: header` with a reserved name | Unbound, with a `reservedHeader` marker carrying the header name and its gap entry | Per the table. Consequence: in a REST operation that also has an `@httpPayload` member, the unbound member is a body member and Smithy's payload validation fails. No prototype service has a reserved header. Alternative to consider in phase 6 (S3 `Content-Length`): keep `@httpHeader` and add `@suppress(["HttpHeaderTrait"])`, which keeps the wire binding as a standard trait |
| `paginators-1.json` | `@paginated(inputToken, outputToken, items, pageSize)` (`PaginatorConversion`) | Converted when Smithy can express it: one input token that is a non-required top-level input member targeting a string or map, one output token path resolving to a string or map. Otherwise no trait and a gap (multiple tokens, missing tokens, a required input token, an unresolvable member). A result key that is not one path to a list or map (CloudWatch's lists of result keys) or a limit key that is not a top-level integral member (Route 53's string `MaxItems`) only drops `items` or `pageSize`, with a gap. `more_results` and `non_aggregate_keys` are recorded as gaps. Map tokens, non-integer page sizes and required output tokens are valid C2J pagination that Smithy flags as DANGER; those operations get `@suppress` for exactly `PaginatedTrait.WrongShapeType` / `PaginatedTrait.ShouldNotBeRequired` |
| `waiters-2.json` | `smithy.waiters#waitable` on each waiter's operation (`WaiterConversion`) | `delay` → `minDelay` (`maxDelay` = delay only when delay exceeds Smithy's 120 s default); `description` → `documentation`. `path`/`pathAll`/`pathAny` with a string → `stringEquals`/`allStringEquals`/`anyStringEquals`; `path` with a boolean → `booleanEquals`; `error` with a code → `errorType`, with `true`/`false` → `success: false`/`true`; `status` 200 → `success: true` (2xx in Smithy, as the published AWS models map it). Any other acceptor (a status other than 200, a numeric expected value) drops the whole waiter with a gap. `maxAttempts` has no Smithy equivalent and is always a `waiter.maxAttempts` gap |
| operation `input.locationName`, `input.xmlNamespace` (rest-xml request root element) | `@xmlName` (only when it differs from the structure name) and `@xmlNamespace` on the input structure (task 1.23) | The candidate mapping from task 1.21. Applied only when every operation using the structure as input agrees on both values and no other shape targets the structure (where the traits would change that member's serialization); otherwise both stay on the `inputMeta` marker. A structure-level C2J `xmlNamespace` wins. Route 53: 22 operations, all converted |
| `endpoint-rule-set.json`, `endpoint-tests.json` | `smithy.rules#endpointRuleSet`, `smithy.rules#endpointTests` | Copied unchanged. Rule sets that use `AWS::Auth::AccountId`, `AWS::Auth::AccountIdEndpointMode` or `AWS::Auth::CredentialScope` get `@suppress(["RuleSetAwsBuiltIn.<built-in>"])`, the advisory DANGER that the published AWS models also suppress (DynamoDB) |

Other decisions:

- **Case-insensitive shape name collisions** (SNS `String`/`string`, `Endpoint`/`endpoint`). Smithy shape IDs must be unique ignoring case. In each group of C2J names that differ only in case, a structure (a generated class) keeps its name; otherwise the name that sorts first (`String.compareTo`, so uppercase first) keeps it. The others get the `C2jShape` suffix (`stringC2jShape`, `endpointC2jShape`; a number is appended if that also collides), every reference is retargeted, and the renamed shape gets a `com.amazonaws.c2j#shapeName` marker with the C2J name plus its gap entry. Operation and service names are also checked ignoring case now.
- **Duplicate query error codes** (CloudWatch `DashboardNotFoundError` and `ResourceNotFound` both use `ResourceNotFound`). This is in the C2J model; for awsQuery, ec2Query and awsQueryCompatible services whose bound errors share a wire code, the service gets `@suppress(["QueryErrorCode"])` and an `error.code(duplicate)` gap.
- **OD-19 markers**, kept with gap entries: `wrapper`, `synthetic`, `operationName`, `resultWrapper` (now only when it is not `<OperationName>Result`), and new markers for member `deprecatedName` and `alternateBeanPropertyName`, the service `authorizers` block and the operation `authorizer`.
- **Markers removed** (fully covered by standard traits): `clientContextParams`, `httpChecksum`, `requestcompression`, `endpointdiscovery`, `endpointoperation`, `staticContextParams`, `operationContextParams`, `contextParam`, `queryName`, `jsonvalue`, `unsignedPayload`, `eventstream`, `event`, `error`. **Narrowed**: `metadata` (only unconverted properties, for example `globalEndpoint`, `serviceAbbreviation`), `http` (operations without `@http`), `hostPrefix` (unbindable labels), `authtype` (unmapped values), `resultWrapper` (non-standard), `inputMeta` (the input reference documentation, plus a root element name or namespace that cannot go on the input structure; task 1.23). **Unchanged**: `required`, `errors`, `outputDoc`, `locationName`. **New**: `shapeName`, `reservedHeader`, `deprecatedName`, `alternateBeanPropertyName`, `authorizers`, `authorizer`.

### Converted prototype models

`ConvertAndAssembleTest` converts the seven fixtures and all five C2J files of each Prototype_Service_Set service, and re-assembles them with the marker definitions and `smithy-aws-endpoints`. All seven services (SQS, Secrets Manager, Account, Route 53, SNS, CloudWatch, DynamoDB) assemble with zero ERROR or DANGER events, so the Route 53 `HttpLabelTrait` and SNS `ShapeIdConflict` failures pinned in task 1.20 are fixed.

Information still only on markers or gap entries, and how task 1.23's IntermediateModel builder does without it (see the `codegen` section):

- `operation.http` on RPC operations: not needed; the rpcv2Cbor request URI is derived from the protocol and the service shape name.
- `shape.required` order: not needed; the generated code is the same with Smithy member order.
- `operation.errors` order and duplicates: the order is kept by the converted model, and the Codegen_Pipeline restores it after re-assembly. Duplicates are dropped, which changes nothing generated.
- `operation.input` (`inputMeta`): converted to `@xmlName`/`@xmlNamespace` on the input structure (task 1.23; row above). Only the input reference documentation stays on the marker, and the generators do not read it.
- `metadata`: `globalEndpoint` (Route 53): not needed. `serviceAbbreviation` (SQS, Route 53, SNS, CloudWatch, DynamoDB): not available, so Javadoc uses `@title` (documentation-only difference).
- Pagination: Route 53 `ListResourceRecordSets` (multiple tokens) and six string `MaxItems` page sizes; CloudWatch `DescribeAlarmsForMetric` (no tokens) and three paginators with several result keys; DynamoDB `BatchGetItem` (required input token). Waiters: `maxAttempts` (Route 53, CloudWatch, DynamoDB) and CloudWatch `AlarmMuteRuleExists` (status 404 acceptor). The Codegen_Pipeline takes these definitions from the sidecar files (`C2jSidecarSupplement`).
- `shape.synthetic` (CloudWatch, DynamoDB), `shape.name` (SNS), `error.code(duplicate)` (CloudWatch), `endpointdiscovery.error` (DynamoDB): not needed for the prototype services' generated code.

## Stage graph built once per client configuration (task 3.30)

Main code adds only a test seam: `SyncApiCallPipeline` and `AsyncApiCallPipeline` each count completed constructions in a `private static final AtomicLong`, read through a package-private `@SdkTestInternalApi static long constructions()`. The increment runs once per pipeline construction, never on the per-call path. Every stage object of a pipeline (transport, `ExecutionAttributesTemplate`, `RequestMutationStages` with its `AuthSchemeResolutionCache`, `RequestSigning`) is created only by the pipeline constructors, so an unchanged count proves a call constructed no stage objects. The counter is on the stage graph rather than on `PipelineCache.pipelinesBuilt()` because the handlers' cache is private to `core.internal.handler` and that method is package-private to `core.internal.http`: exposing it would need a public test-only member. Because the counter is per class loader, tests compare it before and after (surefire runs the `sdk-core` unit tests in one JVM, one test at a time).
