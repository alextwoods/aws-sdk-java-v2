## Rules

- Time is application CPU µs/op (`app_cpu_us_per_op`); memory is client-JVM B/op (`alloc_bytes_per_op`). Means are over all repetitions; error is the 99.9% half-width; ratios are feature mean / Baseline_Build mean
- Floor: the null experiment's max(|ratio − 1|, paired spread) for the operation and metric
- Time (34.4): ratio > 1.05 fails as a regression; otherwise a floor > 5% is inconclusive (34.11); a difference within the floor is "no measurable difference" (34.10)
- B/op (34.3): feature ≤ baseline + floor (floor as a share of the baseline mean)
- B/op vs racecar (37.9): feature ≤ the racecar final build measured in the same run
- Vs bridged (37.10): the recorded numbers come from racecar's run (another host and JDK), so the feature mean is scaled by recorded baseline / measured baseline first. Every difference above 5% needs an expected-cause note in `perf-notes.json`

## Runtime codec bytecode generation (`RuntimeCodegenMode`, Requirement 34.8, OD-6)

Decision: **defer**. smithy-java's runtime codegen defines classes with `Lookup.defineHiddenClass` (JDK 15+) and emits them through a JDK 25 class-file path. A Java 8 version needs a custom `ClassLoader`-based definer and class-version-52 emission, which do not exist yet, so the Java 8 µs/op and B/op for the Requirement 34.1 operations could not be measured. Revisit after the phase 5 numbers are in (design D.3, OD-6).
